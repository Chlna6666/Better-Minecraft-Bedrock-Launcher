# bedrock-render 0.7 API migration

`bedrock-render` 0.7 follows the breaking `bedrock-world` 0.7 responsibility-based API.

The renderer no longer depends on `bedrock-world` crate-root re-exports. World access is imported from the semantic layer explicitly:

```rust
use bedrock_world::{
    codec::NbtTag,
    model::{ChunkPos, Dimension},
    query::SlimeChunkBounds,
    world::{World, ChunkBounds, ChunkLoadOptions},
};
```

## Dependency boundary

```text
bedrock-leveldb -> bedrock-world -> bedrock-render
```

`bedrock-render` may consume high-level world/query/model APIs from `bedrock-world`. Rendering code must not decode Minecraft LevelDB records independently and must not depend on removed world semantics from `bedrock-leveldb`.

Direct `bedrock-leveldb` usage is limited to storage-engine capabilities required by specialized render cache/source implementations. It must remain raw-key/value and storage-oriented.

## Editing

`MapWorldEditor` is the explicit writable boundary. It consumes typed `bedrock-world` APIs and returns render invalidation information. Normal rendering remains read-only.

Historical/future world compatibility is decided by `bedrock-world`; the renderer must not guess old SubChunk, BlockState, biome or actor formats.
