# bedrock-leveldb 0.7 API migration

`bedrock-leveldb` 0.7 is a breaking release that finalizes the crate boundary as a **Mojang LevelDB storage engine**.

It does not expose or interpret Minecraft world semantics. Chunk keys, dimensions, NBT, BlockState, entities, biomes, players and world migration belong to `bedrock-world`.

## Public API

Use the single canonical crate-root API:

```rust
use bedrock_leveldb::{
    CompressionPolicy, Db, LevelDbOpenOptions, ReadOptions, ReadStrategy, ScanMode, VisitorControl,
    WriteBatch, WriteOptions,
};
```

The earlier draft `access`, `engine`, `format`, and `io` public modules were never implemented and
are not compatibility aliases. Version 0.7 exposes one authoritative path for every public type.

## Responsibilities

### Database engine

Database lifecycle and stateful operations:

- `Db`
- `LevelDbOpenOptions`
- snapshots and iterators
- cache/statistics
- repair
- compaction

### Raw access

Arbitrary raw byte access:

- borrowed key/value views
- read options and strategies
- sequential/parallel scan policy
- cancellation and progress
- visitor control

### Physical format

Mojang LevelDB physical write policy:

- `WriteBatch`
- `WriteOp`
- `CompressionPolicy`
- `ChecksumMode`
- `WriteOptions`

### Internal I/O

Low-level file/mmap/buffer-pool infrastructure. This namespace must remain world-format agnostic.

## Compatibility contract

Historical Minecraft versions may use different world records, but that is intentionally invisible here. If the underlying Mojang LevelDB representation is readable, this crate returns the exact raw key/value bytes.

The storage layer must never guess:

- a chunk-key layout,
- a dimension,
- a SubChunk version,
- a BlockState migration,
- an actor/entity schema.

Those are `bedrock-world` responsibilities.

## Performance contract

The 0.7 implementation continues to prioritize:

- borrowed/zero-copy-oriented reads where lifetime permits,
- batched point lookups,
- bounded parallel scans,
- block/index cache locality,
- reusable buffers,
- WAL-backed writes,
- last-write-wins batch compaction,
- native Mojang compression variants,
- deterministic repair/compaction semantics.

Performance work must not introduce Minecraft semantic knowledge into this crate.
